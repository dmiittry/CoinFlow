## Автоматический импорт банковских операций — 2026-10-03

- Пользователь спросил, можно ли подключить SMS или банки для поступления расходов и как это реализовать. Это консультация; код, разрешения телефона и сервер не изменялись.
- Предложение для первого этапа: Android — локальный разбор уведомлений выбранных БАНКОВСКИХ приложений через NotificationListenerService с явным доступом пользователя; SMS как отдельный вариант с READ_SMS/RECEIVE_SMS и проверкой допустимости. Не использовать уведомления приложения SMS для обхода правил SMS-доступа.
- Google Play предусматривает исключение SMS-based money management, но оно требует декларации, выполнения условий и одобрения, которое не гарантировано: https://support.google.com/googleplay/android-developer/answer/10208820?hl=en . Не утверждать, что SMS в Play безусловно запрещены или безусловно разрешены.
- Обычному финансовому приложению iOS нельзя обещать доступ ко всем SMS и уведомлениям других приложений. TelephonyMessagingKit — отдельное приложение обработки сообщений по умолчанию, пользователь и аккаунт в ЕС; для CoinFlow России/США это не подходящий универсальный путь. https://developer.apple.com/documentation/telephonymessagingkit/creating-a-carrier-messaging-app . FinanceKit доступен для определённых продуктов/банков США и Великобритании с entitlement: https://developer.apple.com/financekit/ . Это не подключение российских карт.
- Прямые подключения: банк/агрегатор с согласием клиента → Django (токены и проверка/обновление операций) → Flutter. Для РФ нет подтверждённого универсального доступа для CoinFlow ко всем банкам; открытые API развиваются, условия проверять по банкам: https://cbr.ru/fintech/api/ . За рубежом кандидат Plaid Transactions; отдельно проверять покрытие банка/продукта и допуск нашего юридического лица: https://plaid.com/docs/transactions/ . API эквайринга не означает доступ к личным расходам.
- Нужны адаптеры банковских форматов, сопоставление карты/кошелька, очередь распознанных операций, ручное подтверждение неоднозначных записей, защита от повторов и сверка со выпиской. Различать расходы, доходы, возвраты, собственные переводы и блокировки; не считать остаток суммой покупки. Первоначально подтверждать распознанное, после проверки разрешать автоматическое принятие надёжных шаблонов по выбору пользователя.
- Уведомления могут отсутствовать, скрывать текст, повторяться; это не полная банковская история. SMS/уведомления можно обрабатывать офлайн без Django; банковский API — отдельный серверный этап. CSV-выписки требуют адаптеров: нынешний формат импорта приложения не универсальная банковская выписка.
- На вопрос о банках пользователь ответил: «вообщем как это система работает? любой банк для примера сделай тбанк». Объяснение строится на Т-Банке; это запрос примера работы системы, не подтверждённая задача подключения реального счёта.
- У Т-Банка подтверждены оповещения об операциях в SMS/push: https://www.tbank.ru/bank/help/interfaces/bank-app/security/self-protect/ . Найденный публичный API выписок относится к Т-Бизнесу и операциям компании, не доказывает доступ к личным картам физлиц: https://developer.tbank.ru/docs/api/get-api-v-1-statement . Пример текста уведомления в объяснении условный, не проверенный парсер реального банковского формата.
- Пользователь уточнил, может ли само приложение читать уведомления iOS/Android. Объяснение: Android — отдельный NotificationListenerService и специальное системное разрешение пользователя; обычный запрос на показ уведомлений не даёт их чтения. Kotlin-служба фильтрует банковские приложения, сохраняет очередь распознанных операций; Flutter читает очередь через платформенный мост/БД. Сервис не должен полагаться на постоянно открытый Flutter-экран; работа зависит от доступного текста, системных ограничений и доставки.
- iOS — обычное финансовое приложение не получает общий доступ к чужим уведомлениям; Notification Service Extension обрабатывает уведомления своего приложения. Ограничение нельзя снять выбором Flutter/Swift или обычным согласием на показ push. Банковские API и импорт пользовательских выписок остаются возможными при доступности интеграции. Источники: https://developer.apple.com/documentation/usernotifications/unnotificationserviceextension ; https://developer.android.com/reference/android/provider/Settings#ACTION_NOTIFICATION_LISTENER_SETTINGS .
