# Контракт будущего Django API

Сервер пока не реализован и приложение его не вызывает. `main.dart` создает только `LocalFinanceRepository`. Подготовлен адаптер `DjangoFinanceRepository`, получающий `http.Client`, URL и access token через конструктор. Переключать его нужно после реализации и проверки сервера.

## Этап подключения

1. Django + Django REST Framework, пользовательские данные фильтруются по `request.user`.
2. Авторизация: `POST /api/v1/auth/token/` с `username`, `password`, в ответ access/refresh. Демовход заменить серверной авторизацией, токены хранить в Keychain/Keystore. Сейчас пароль никуда не передается.
3. `GET /api/v1/finance/snapshot/` → HTTP 200, JSON `FinanceData.toJson()`, заголовок `ETag: "revision"`.
4. `PUT` на тот же URL с JSON и `If-Match` → транзакционная замена пользовательского снимка, HTTP 200/204 и новый ETag. Несовпадение версии → 412. ETag должен проверяться атомарно в БД.
5. Для web при отдельном origin настроить CORS для приложения и expose header ETag.

## Данные

```json
{
  "version": 1,
  "cards": [{
    "id": "unique-client-id", "name": "Карта", "kind": "wallet",
    "opening": 150000, "budget": 0, "icon": "wallet",
    "opening_date": "2026-10-03T00:00:00.000"
  }],
  "entries": []
}
```

- Все суммы — целые копейки, валюта этого этапа — RUB.
- `kind` карточки: income / wallet / expense.
- Поля операции: id, kind (income / expense / transfer), wallet_id, target_id, amount (>0), date, note.
- Для income/expense target_id указывает на соответствующую категорию. Для transfer — на другой кошелек. Один перевод сохраняется одной операцией.
- Даты сейчас локальные календарные даты; при серверной интеграции согласовать timezone пользователя и сериализацию времени.
- Проверки сервера должны повторять доменные проверки, ограничивать размеры, проверять владельца всех ссылок, уникальность ID и имен внутри группы.
- Снимок не является алгоритмом синхронизации: нет фонового обмена, очереди офлайн-изменений и автоматического разрешения конфликтов. Это следующий отдельный этап.

## Локальное хранение

Для тестовой версии используется один JSON-снимок в SharedPreferences. Сохранение ожидается до изменения UI; ошибка чтения не затирает данные. Для выпуска и больших объемов заменить локальный адаптер на транзакционную SQLite/Drift БД, добавить миграции, защищенную авторизацию и резервное восстановление.
