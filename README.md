# CoinFlow

Flutter-приложение учета личных финансов для Android и iOS. Интерфейс повторяет структуру приложенных скриншотов: доходы, кошельки, расходы, круглые карточки и заполнение лимитов. Рабочая тестовая версия без сервера.

Репозиторий: [dmiittry/CoinFlow](https://github.com/dmiittry/CoinFlow), основная ветка `main`.

```sh
git clone https://github.com/dmiittry/CoinFlow.git
cd CoinFlow
flutter pub get
```

## Возможности

- Тестовый вход и сохранение сессии; выход не удаляет данные.
- Создание и редактирование доходов, расходов и переводов; история с поиском, фильтрами по типу и кошельку, просмотром за месяц или за всё время.
- Добавление, переименование и удаление карточек, выбор иконок, начальные остатки, месячные планы и лимиты.
- Нажатие на карточку открывает операцию, карандаш — настройки. Удержание с перетаскиванием кошелька на расход, дохода на кошелек или кошелька на другой кошелек заполняет форму. Обычный свайп прокручивает экран.
- Удаление операции требует подтверждения, пересчитывает суммы и допускает отмену через уведомление. Карточку со связанными операциями удалить нельзя.
- Недостающие кошельки и категории можно создать прямо из формы операции. Повторные нажатия во время сохранения блокируются; при ошибке введённые данные остаются в форме.
- Выбор месяца календарём, стрелками и возврат к текущему месяцу. Новая операция в прошедшем месяце получает дату этого месяца; для будущего месяца используется сегодня. Дату начальной суммы категории можно изменить отдельно.
- Системная тема по умолчанию, светлая и темная темы по выбору.
- Суммы хранятся в целых копейках. Валюта этой версии — рубль.
- Кошельки показывают текущий остаток независимо от выбранного месяца. Доходы и расходы относятся к выбранному месяцу. Начальные суммы категорий относятся к месяцу их даты.
- Первый запуск содержит демонстрационные операции по мотивам референсов. Сводные суммы вычисляются из данных, а не копируются с изображения.
- В настройках можно начать с пустой базы или восстановить предыдущую сохранённую версию. Перед заменой базы сохраняется одна предыдущая версия; следующее изменение обновляет её. CSV нужен для долговременных резервных копий.

## CSV

В настройках доступны экспорт полной базы, импорт и три шаблона: нулевые остатки, пример с суммами и формат полной копии. Файлы также лежат в `templates/`:

- `initial_balances.csv` — пример с заполненными суммами;
- `empty_balances.csv` — нулевые остатки для старта;
- `full_backup.csv` — пример полной базы с карточками, лимитами и историей.

Простой шаблон содержит **одну строку снимка** и произвольное число колонок `Доход: Имя`, `Кошелек: Имя`, `Расход: Имя`. Карточки создаются из имен колонок, в том числе при нулевой сумме. Суммы доходов/расходов не меняют остатки кошельков в этом формате: каждая колонка задает самостоятельный итог. Это не формат строк отдельных операций.

Полная копия имеет три раздела: Доходы, Кошельки, Расходы. Поле `Запись` различает карточки и операции; переводы относятся к Кошелькам. ID сохраняют связи между сущностями. Экспорт и обратный импорт сохраняют все поля.

Поддерживаются UTF-8 с BOM или без, `;` или `,` как разделитель, экранированные кавычки, переносы строк внутри поля, десятичная запятая. Дата: `ГГГГ-ММ-ДД`. Максимум 5 МБ. Некорректный файл не меняет данные. После проверки показывается состав файла; импорт **заменяет** текущую базу после отдельного подтверждения. Для сохранения прежней базы сначала используйте экспорт.

Пустая база также экспортируется и импортируется. Ошибочные даты, дубли названий/ID, потерянные связи, неправильная кодировка и недопустимые суммы отклоняются. При отмене системного диалога сохранения сообщение об успешном экспорте не появляется. В браузере сообщается о передаче CSV на скачивание.

### Импорт экспорта CoinKeeper

CSV CoinKeeper распознаётся автоматически через «Настройки → Импорт CSV». Основные колонки: `Date,Type,From,To,Amount,Currency`; также читаются `Tags,Amount converted,Currency of conversion,Recurrence,Note`. Порядок колонок может отличаться. Поддерживается исходная дата `ДД.ММ.ГГГГ`, UTF-8, запятая или точка с запятой между полями, кавычки и многострочные комментарии.

- `income`: From — источник дохода, To — кошелек.
- `expense`: From — кошелек, To — категория расхода.
- `transfer`: From — исходный кошелек, To — получатель.
- Карточки создаются по названиям; одинаковые названия внутри раздела с разным регистром/пробелами по краям объединяются. Между разделами названия независимы. Одинаковые строки операций не удаляются как дубли.
- Комментарии сохраняются. Метки и параметры повторения добавляются в комментарий; автоматическое повторение не включается. Категория `correction` сохраняется с исходным названием и типом операции из CSV.
- Поддерживается **RUB**. Иностранные валюты и мультивалютные переводы отклоняются с номером записи. Конвертация RUB → RUB допустима при совпадении сумм; она не создаёт вторую операцию.

В файле операций нет начальных остатков и лимитов: они устанавливаются в ноль. Баланс вычисляется по загруженной истории и может отличаться от CoinKeeper, особенно при экспорте неполного периода. Начальные остатки можно уточнить в карточках кошельков. Даты сохраняются как календарные даты из CSV, без сдвига по часовому поясу в имени файла.

Перед записью показываются формат, количество карточек/операций и пояснения. До явного подтверждения база не меняется. Ошибка любой записи отклоняет весь импорт, без частичного сохранения. Импорт заменяет базу, а не дописывает операции. Собственный формат экспорта CoinFlow остаётся прежним.

Для проверки чтения файла без открытия базы приложения:

```sh
dart run tools/check_csv.dart "path/to/export.csv"
```

Команда выводит только формат и количества записей, ничего не сохраняет. Тестовые примеры CoinKeeper в тестах вымышленные; личные выгрузки в репозиторий добавлять не нужно.

## Архитектура

- `lib/domain` — модели, проверки и расчеты.
- `lib/application` — состояние и сценарии приложения.
- `lib/data` — локальное хранилище, CSV, отдельный подготовленный Django REST адаптер.
- `lib/ui` — интерфейс и темы.
- `docs/DJANGO_API.md` — контракт будущего сервера и порядок подключения.

В работающем приложении подключен только `LocalFinanceRepository`. Django-сервера, фоновой синхронизации и настоящей серверной авторизации пока нет. Адаптер API проверен mock-тестом; настоящий сервер не тестировался.

Локальная тестовая база хранится JSON-снимком в SharedPreferences. Это не зашифрованная производственная БД; для выпуска требуется заменить адаптер на SQLite/Drift и тестовый вход на серверную авторизацию. Удаление приложения или очистка данных браузера удаляет локальную базу, поэтому предусмотрен CSV-экспорт.

При повреждении или отсутствии основной записи приложение пробует предыдущую копию и сообщает о восстановлении. Если обе копии не читаются, показывается ошибка с повторной загрузкой; демонстрационные данные не записываются поверх повреждённых. Ошибки записи не меняют видимые данные; перед следующим сохранением хранилище перечитывается.
